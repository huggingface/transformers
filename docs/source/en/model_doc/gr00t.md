# GR00T

[GR00T N1](https://huggingface.co/papers/2503.14734) is NVIDIA's open foundation model for generalist humanoid robots. It is a vision-language-action model: a vision-language backbone reads the camera images and the language instruction, and a diffusion transformer (DiT) trained with flow matching generates a chunk of robot actions conditioned on the backbone features and the robot state.

This implementation targets GR00T N1.7:

- The backbone is [Cosmos-Reason2-2B](https://huggingface.co/nvidia/Cosmos-Reason2-2B), a [Qwen3-VL](qwen3_vl) model whose language model is truncated to its first 16 layers. The action head reads the output of the last decoder layer before the final norm.
- The backbone features go through a LayerNorm and 4 self-attention blocks, then condition a 32-block DiT. Even blocks cross-attend to the backbone features, alternating between the text tokens and the image tokens, and odd blocks self-attend to the state and action tokens. The timestep conditions the DiT through adaptive layer norms.
- The state encoder, action encoder and action decoder hold one set of weights per embodiment (robot type), selected with `embodiment_id`.
- Actions are generated by integrating the predicted velocity field from noise (`t=0`) to actions (`t=1`) with 4 Euler steps.

The abstract from the paper is the following:

*General-purpose robots need a versatile body and an intelligent mind. Recent advancements in humanoid robots have shown great promise as a hardware platform for building generalist autonomy in the human world. A robot foundation model, trained on massive and diverse data sources, is essential for enabling the robots to reason about novel situations, robustly handle real-world variability, and rapidly learn new tasks. To this end, we introduce GR00T N1, an open foundation model for humanoid robots. GR00T N1 is a Vision-Language-Action (VLA) model with a dual-system architecture. The vision-language module (System 2) interprets the environment through vision and language instructions. The subsequent diffusion transformer module (System 1) generates fluid motor actions in real time. Both modules are tightly coupled and jointly trained end-to-end. We train GR00T N1 with a heterogeneous mixture of real-robot trajectories, human videos, and synthetically generated datasets. We show that our generalist robot model GR00T N1 outperforms the state-of-the-art imitation learning baselines on standard simulation benchmarks across multiple robot embodiments. Furthermore, we deploy our model on the Fourier GR-1 humanoid robot for language-conditioned bimanual manipulation tasks, achieving strong performance with high data efficiency.*

This model was contributed by [rickygrosvenor-pramanick](https://github.com/rickygrosvenor-pramanick).
The original code can be found [here](https://github.com/NVIDIA/Isaac-GR00T), and the checkpoint [here](https://huggingface.co/nvidia/GR00T-N1.7-3B). The [LeRobot GR00T policy](https://github.com/huggingface/lerobot/tree/main/src/lerobot/policies/groot), a reimplementation of N1.7 on top of Transformers' Qwen3-VL, was a useful reference for this port.

The checkpoints are released under the NVIDIA Open Model License: see the [model card](https://huggingface.co/nvidia/GR00T-N1.7-3B) for its terms.

## Usage example

The original checkpoints store their processor settings in the Isaac-GR00T format, and load the tokenizer from the gated [Cosmos-Reason2-2B](https://huggingface.co/nvidia/Cosmos-Reason2-2B) repository. Convert a checkpoint once, after accepting the terms of that repository and logging in:

```bash
python src/transformers/models/gr00t/convert_gr00t_to_hf.py --checkpoint nvidia/GR00T-N1.7-3B --output_dir gr00t-n1.7-3b
```

The processor formats the instruction, preprocesses the camera images and normalizes the robot state with the statistics of the embodiment. The model generates a normalized action chunk, which the processor maps back to the action space of the embodiment.

```python
import numpy as np
import torch
from PIL import Image

from transformers import Gr00tForConditionalGeneration, Gr00tProcessor

processor = Gr00tProcessor.from_pretrained("gr00t-n1.7-3b")
model = Gr00tForConditionalGeneration.from_pretrained("gr00t-n1.7-3b", dtype=torch.bfloat16, device_map="auto")

embodiment = "oxe_droid_relative_eef_relative_joint"
video_config = processor.modality_configs[embodiment]["video"]
print(video_config["modality_keys"], video_config["delta_indices"])  # the camera views, and the frames of each view
# Replace with the camera images: 2 frames (15 steps ago and now) of the 2 views, ordered frame first, then view
images = [Image.new("RGB", (320, 240)) for _ in range(4)]
state = {  # replace with the robot state of each joint group
    "eef_9d": np.zeros((1, 9)),
    "gripper_position": np.zeros((1, 1)),
    "joint_position": np.zeros((1, 7)),
}

inputs = processor(
    images=[images], text="pick up the bowl", state=state, embodiment_tag=embodiment, return_tensors="pt"
).to(model.device)
normalized_actions = model.sample_actions(**inputs)
actions = processor.post_process_actions(normalized_actions, embodiment, state=state)
print({key: value.shape for key, value in actions.items()})  # (1, 40, dim) for each joint group
```

## Training

Pass the raw action chunk of each joint group as `actions` to the processor. It converts the relative groups to the frame of the current state, normalizes them, and pads them to `max_action_dim`, returning `actions` and the `action_mask` of their valid entries. The model then returns the flow-matching loss.

```python
actions = {  # the next 40 steps of each joint group
    "eef_9d": np.zeros((1, 40, 9)),
    "gripper_position": np.zeros((1, 40, 1)),
    "joint_position": np.zeros((1, 40, 7)),
}
inputs = processor(
    images=[images], text="pick up the bowl", state=state, actions=actions, embodiment_tag=embodiment, return_tensors="pt"
).to(model.device)

model.train()
loss = model(**inputs).loss
loss.backward()
```

During training, the model drops the state embedding of a sample with probability `state_dropout_prob`. The original GR00T training pipeline also replaces the normalized state input of a sample with zeros with probability 0.2 in its processor (`state_dropout_prob` of the original `processor_config.json`). To reproduce it, zero `inputs["state"]` for a random subset of the batch before the forward pass.

```python
keep_state = torch.rand(inputs["state"].shape[0], device=inputs["state"].device) >= 0.2
inputs["state"] = inputs["state"] * keep_state[:, None]
```

The image processor pads non-square camera images to a square before resizing, as the original GR00T N1.7 release (`n1.7-release` tag) does whatever the `letter_box_transform` setting.
