# PI0.5

[PI0.5](https://huggingface.co/papers/2504.16054) is a vision-language-action model for robot manipulation from Physical Intelligence. It keeps the [PI0](./pi0) layout: a PaliGemma backbone reads the camera images and the prompt, and a smaller Gemma action expert predicts a chunk of actions with flow matching.

PI0.5 changes two things compared to PI0:

- The robot state is not projected into the action expert. The processor discretizes it into 256 bins and writes the bin indices into the text prompt (`Task: ..., State: ...;\nAction: `).
- The action expert receives the denoising timestep through adaptive RMS norms. Each norm predicts a scale, a shift and a residual gate from the timestep embedding. The action tokens themselves only carry the noisy actions.

The processor expects a state and actions that are already normalized the way the checkpoint was trained, with the normalization step of the LeRobot pipeline. The state must be in [-1, 1].

The original code can be found [here](https://github.com/Physical-Intelligence/openpi). The checkpoints are the LeRobot ones, for example [lerobot/pi05_base](https://huggingface.co/lerobot/pi05_base). LeRobot fine-tuned checkpoints, which store the weights under an extra `model.` prefix, load as well.

## Usage examples

```python
import torch

from transformers import PI05ForConditionalGeneration, PI05Processor
from transformers.image_utils import load_image


model = PI05ForConditionalGeneration.from_pretrained("lerobot/pi05_base", device_map="auto")
processor = PI05Processor.from_pretrained("google/paligemma-3b-pt-224")

image = load_image("https://huggingface.co/datasets/huggingface/documentation-images/resolve/main/transformers/vla_pi0.jpg")
state = torch.rand(1, 8) * 2 - 1  # replace with the normalized robot state
inputs = processor(image, "Pick up the object", state=state, return_tensors="pt").to(model.device)

actions = model.sample_actions(**inputs, num_steps=10)
print(actions.shape)
```
